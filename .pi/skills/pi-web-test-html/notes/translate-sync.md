# 用例集：预览翻译 → 同步回原文（translate-sync）

盯的是 PR #418 / D245 修订那条链：日文 md 在预览里翻成中文 → 人手改某节译文 → 点「同步原文」→ 桥把改动折回**日文**原文。

## 为什么用桩 pi，而不是真模型

真模型（`wb2api/cn:deepseek-v4.1-flash`）能翻，但每次跑书都要花 turn、依赖本机网关和代理，且反向折回的日文措辞每次不同 —— 断言只能写「大概」。桩 pi（`.scratch/testbook/translate-sync/env/fake-pi.mjs`，行形参见 `bridge/tests/fixtures/fake-pi-translate.mjs`）把两个方向都钉死：

- 正向：逐行去假名、加「译 」前缀，标题保留 `#` 号，**吞掉 `---` 分隔线**（真模型也这么干，这正是「整节重译」的触发源）。
- 反向：改动块写回「原文标题 + についてのご案内」（假名 11）；非标题块接一句 `この件についても中止してください。`

于是旧代码（`9569afb`）必然红、新代码必然绿，任何机器上结论一致。

## 两处容易写歪的断言

1. **别整框替换编辑框**。`textarea.tr-sed` 装的是**整节**（标题 + 正文）。用 `fill("## 新标题")` 会把正文一起删掉，块数从 2 变 1 → 桥走「段落结构变了，这一节整节重译」——那是另一条合法分支，不是被测的 bug。只替换标题行：`before.replace(/^(#{1,6}\s+).*$/m, EDIT_TO)`。
2. **找对那一节的右栏**。TC-05 要读 `tbody.tr-row` 的 `.nth(hit)`；`.first()` 是第 1 节，会读到没改过的那行，永远绿。

## 红/绿口径

- 红：`确认页里出现：写回的是日文，原文不是、这一块没有写回、整节重译`（用户截图原句）。
- 绿：`2 块改动；没有误判告警`，写回后左栏标题是日文，磁盘上 `---` 与正文原样。

同一本书在修复前的 worktree（`chore/verify-prefix @ 9569afb`）跑是 3/6，这条 3/6 就是修好的证据形状。
