# 提醒中心 · 状态机原型（一次性）

**这份原型要回答的问题：** 一条提醒只有四种归宿 —— 「还在等你」「处理完了（批了 / 拒了 / 答了）」「已读」（只对构建失败这类非阻塞的事）、「已失效」（桥重启）。把「静音一个会话」「一个会话连着要十次审批」「桥半夜重启」「五百条一起塞进来」推过去，角标与清单还自洽吗？

旁边 `../reminders-ui/` 回答的是**长什么样**，这份只管**状态对不对**。

## 怎么跑

双击 `index.html`。没有构建、没有后端、没有计时器 —— 时间是一条虚拟时钟，「+30 秒」「+1 小时」「+8 天」点一下就到。

## 页面里有什么

1. **当前状态**：角标数字、吐司一共弹了几条、虚拟时钟，然后是「在等你」与「处理过 / 失效」两列，最后一行是「刚才弹的」。每次点击整份重画，并单独用一行说**这次变了什么**。
2. **自由点**：按「有人来找你 / 你动手了 / 系统 / 时间」四组摆开，随便点。
3. **跟着走一遍**：五个场景，每个场景下面是一排按顺序的按钮（点第几步就跑第几步），换场景会先清空。

## 值得留下的那块

`index.html` 中间「可以整段拎走的纯逻辑」那一段：`emptyStore / raise / settle / read / mute / unmute / restart / prune / badge`。它**不碰 DOM、不读时钟**（`now` 一律由外面传进来），可以整段搬进 `bridge/src/reminders.ts`，常量就是 `KEEP_DAYS / CAP / COALESCE_MS`。页面（渲染、按钮、场景）是抛的。

## 原型自己踩过的坑（值得带进实现）

第一版把「上次弹吐司的时间」的缺省值写成 `?? 0`，虚拟时钟也从 0 起 —— 于是**第一条吐司被自己吞掉**，角标 5、吐司 0，页面上还理直气壮写着「只弹 1 条」。改成 `?? -Infinity` 才对。

这件事的教训不是「虚拟时钟要小心」，而是：**「还没弹过」与「在 0 时刻弹过」在语义上是两件事，用一个时间戳既当哨兵又当历史就会撞**。落地时 `bridge/src/reminders.ts` 的 `lastToastAt` 要显式区分「没有记录」，并且 `bridge/tests/reminders-unit.mjs` 第一条用例就该是「第一次 raise 一定要弹、第二次 30 秒内不弹」。
